# Harness model evaluation

Use Mortimer as Larry's interface. External subscription CLIs are implementation details. This skill supplies instructions; it does not grant tools, account access, spending authority, or permission to change a model.

Apply to requests about harness/controller model evidence. A generic daily brief request is not a request for this evaluation. Capability/tool admission is enforced only by the opt-in v2 selector; the legacy matcher selects instructions without granting execution authority.

1. Establish mode: **daily brief**, **evaluation plan**, **authorized review**, or **model proposal**. A daily check never implies authorization for the other modes.
2. Read [evidence and baseline](references/evidence-baseline.md). Date each source. Separate official documentation, account eligibility, adapter compatibility, and measured harness results. Missing evidence stays unknown. A release announcement is not proof of account access or superiority.
3. For the brief, use Mortimer's cached `status_models` report; inspect its `harness_brief` field; explicit document refresh is available only through Mortimer’s native “Refresh official model evidence” button; follow [daily brief](references/daily-brief.md). Do not invoke subscription probes, inference, external reviewers, credentials, purchases, or configuration tools. Keep the current model unless Larry approves a concrete change.
4. For evaluation, use [evaluation design](references/evaluation.md). Start with offline contracts and a small bounded experiment proposed for separate authorization. Use synthetic data only. Never treat the historical single capability sessions as a benchmark.
5. Invoke an independent reviewer only with explicit authorization for this review and its immutable input; follow [review protocol](references/review-protocol.md). Stop on model mismatch, eligibility failure, permission denial, or exhausted quota. Never substitute a model or payment route.
6. Present a proposal inside Mortimer with exact current/candidate model, route, eligibility, evidence quality, latency/quality tradeoffs, privacy, quota/cost, validation state, and outstanding gaps. Follow [Mortimer contract](references/mortimer-integration.md). A recommendation is not confirmation. Never call confirmation on Larry's behalf merely because a recommendation favors a candidate.
7. Harness switching is currently blocked pending a durable approval contract across every applicable writer and runtime. Do not offer usable switching or claim the routed selection is the active voice model. Distinguish **drafted**, **confirmed and saved**, **runtime adoption unverified**, and **verified active**. Rollback is another explicit exact proposal unless it is a previously authorized atomic failure rollback before adoption. No silent fallback.

Direct Anthropic and OpenAI APIs are excluded. Claude Max and ChatGPT subscription paths are preferred. Other providers' APIs remain eligible as separately approved options with explicit cost/privacy controls. Never widen this exclusion to all APIs or narrow it to only paid inference.

Return a concise recommendation, dated evidence with uncertainty, next authorized action, and any blocker. Preserve review dispositions and input hashes. Do not start services, install, publish, schedule automation, run benchmarks, or switch models as a side effect of this skill.
