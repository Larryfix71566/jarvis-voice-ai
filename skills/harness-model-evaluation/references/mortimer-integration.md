Its future mobile presentation/admission adapter reuses the same host records and state transitions; model management is deferred beyond the initial phone slice. No second registry, evaluator or auto-selection policy.

Existing user-facing daily hook is the status job's `daily_status` notice, spoken on the next greeting via `jarvis.notices`. The comprehensive mail/calendar daily brief remains a design document; its proposed `daily_brief` tool is not an established implemented endpoint. The existing status job and health checks are preserved. A separate passive hook reads local cache/metadata only and emits a deduplicated notice; it never adds provider calls. The explicit Mortimer refresh action fetches fixed public documentation only. Services remain stopped until a separate deployment decision.

Target future complete flow (not implemented switching): brief recommendation → inspect dated sources/unknowns and comparable results → request a bounded evaluation if needed → inspect exact proposal → Larry explicitly confirms that proposal → save atomically → report configured readback and runtime adoption separately. A daily recommendation can never execute the confirmation operation. Replayed, expired or stale approvals must fail; a changed current model, profile resolution, route, endpoint, privacy/capability policy or saved preference revision requires a fresh preview. The existing native panel is the first presentation; future voice/phone admission must bind the same proposal, not infer approval from an unrelated “yes”.

Each proposal should show current and candidate exact model, workload, route/adapter, subscription eligibility, evidence quality, expected latency/quality, privacy impact, quota/cost and validation gaps. Digest the immutable proposal and bind confirmation to it. Credentials are never in a proposal. Use a host-owned identity/capability token, expiry and a transaction to consume it once. Existing local admin authentication remains the trust boundary; this does not defend against a malicious process already holding equivalent local authority.

Saving a route preference does not prove the active voice session changed. A narrow confirmation patch must say “saved; runtime adoption unverified” until runtime ACK names exact model/config revision. Do not hot-swap an in-flight run, claim applied on HTTP success alone, restart stopped services, or create hidden fallback. Stronger durable exact-model pinning across later registry edits and runtime ACK/rollback require explicit provider/runtime integration; do not pretend a UI-only gate covers those separate writers.

Rollback requires a fresh exact proposal to the previous recorded choice and the same eligibility/privacy checks, plus Larry's confirmation. An automatic rollback is permissible only inside the already approved atomic transaction before adoption and to its exact pre-state; no silent switch to a default model. Missing runtime ACK is reported, not “fixed” by a fallback call.

R2 implementation boundary: voice_supervisor stage and confirm are blocked on the backend and disabled in the native panel. Older voice drafts cannot bypass the block. The LLM-callable voice model_route confirmation always refuses: it is not trusted human admission. Nonvoice native selections have exact resolved proposal digest, expiry, stale/replay checks and transactional save/readback, but remain mutable profile-label preferences after save. They are not a durable model pin or evidence of runtime adoption. No new claim covers environment/config/self-edit writers. The complete harness gate requires provider/runtime owner work across Settings, registry, preference writes and execution; existing writers remain unchanged. Harness switching must remain unavailable until that contract is implemented and validated.
