# Evaluation design

Canonical detailed plan: Library `libfile_502deeb949688191a3c41f02eafadb4c`, version 2, `MORTIMER_CONTROLLER_TEST_PLAN.md`, SHA256 `23fd4aed98c3e86a2d31ee4a4a0fa26568bd7de8c2a0fb7b330c8b8cce840343` (2026-10-22). Use the plan's current reviewed lineage; do not run historical commands automatically.

Compare A: one stronger Claude controller; B: local responsive controls plus the same stronger controller; C: future Codex app-server controller, only after adapter readiness. Reuse A's intelligence evidence for B; test B's local controls offline and integrated timing later. Claude bridge buffers complete output; current Codex text adapter refuses native tools. Model intelligence and adapter readiness are different gates.

Stage 0: fake-provider contract tests, deterministic synthetic tools, no inference. Cover schema validation, exact UI targets, duplicate suppression, failure propagation, cancellation, no fallback, privacy, queue ownership and context accounting. These prove host behavior, not intelligence.

Stage 1: separately authorize at most two stronger Claude candidates after exact ID/account eligibility verification. First two four-turn development sessions (8 turns/model) are included in the full initial 12-family, one-variant, four-turn experiment (48 turns/model, ceiling 192 requests/model; max 384 for two candidates). An optional baseline is a separate budget. One controlled context/effort/cold condition, no speculative repeats. The twelve families cover quality/relevance, context retention, correct UI targeting, valid tools, weather city/cache, roadmap truthfulness, interruption/cancellation, failed tools, duplicates, escalation, privacy refusal and hidden fallback. Initial cancellation is turn-boundary/fake-pending; actual midstream cancellation belongs in later integration.

Stop on shared host failure; fix offline before inference resumes. Reject attributable critical model failures. Below 36/48 is not promising; at least 42/48, zero critical failures and a lead of at least five (or a sole survivor) permits a recommendation for a separately authorized integration smoke. Two survivors at least 42/48 within four are a practical tie. Borderline 36–41 or unresolved cases may justify focused Stage 2. These are selection heuristics, not population estimates.

Stage 2 only if needed: 96 held-out turns, optional 32 targeted repeat turns and 24 long-context probe turns, maximum 152 turns/608 requests per survivor. Primary threshold 84/96 and lead ten; repeats/long-context remain separate diagnostic strata. Stage 3 formal confirmation is optional: 384 turns/1536 requests per model with fresh sealed cases. Neither hundreds nor thousands of calls are prerequisite to learning which option is promising, and none are pre-authorized.

Freeze cases, oracle, context, effort, tool schemas and model identity before calls. Alternate order; blind model labels where possible; use exact denominators and M(model)/H(host)/J(joint or uncertain) failure attribution. Separate teacher-forced contract/decision checks from closed-loop accumulated-context results. Larry can be the single exploratory scorer; independent scoring is a later confirmation choice. Hash-sealing by the author is procedural holdout, not true blinding. Oracle-only corrections rescore offline; input changes require explicit bounded rerun budget.

Timing: actual speech end → final transcript; → first useful feedback; → first text; → complete validated action; → independently verified result; → playback onset. Cancellation request → cancellation acknowledged and → all relevant work stopped. Record the known 2.5-second silence window separately from CLI cold start, queue delay, tools, context preparation and model generation. Report sample counts, missing/failure/timeouts, cold/warm strata, p50 and range for exploratory runs; p95 only with adequate independent integrated samples and honest uncertainty. Never use a final buffered response as a first-token measure.

Selection is safety first, then task quality/context, correct tools/results, relevant latency, quota/cost, maintainability and adapter maturity. Uncertain differences are ties. No update without the exact in-app proposal and Larry's confirmation. No production claims: Mortimer is a single-user development app.

Lead/tie rules compare stronger candidates only; the baseline difference is descriptive. No selection if the baseline matches/exceeds all candidates unless Larry decides otherwise. Stage 1 is S-context-only. Critical M assertions are tagged before calls. Cap failures are attributed; two adapter-caused cap failures halt the shared path. Let in-flight requests finish on deadline or use only an offline-validated owned-process cleanup contract, accounting for uncertain usage. Stage 3 requires a fresh sealed set after any Stage 2 scoring. Same-model A/B shares Q; initial integration uses L/R/U/H, with no duplicate intelligence calls or mandatory Stage 3.
