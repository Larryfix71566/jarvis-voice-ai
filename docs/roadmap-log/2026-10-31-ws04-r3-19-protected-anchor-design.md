**Implemented boundary:** exactly the three source paths above changed. Inject a narrow Security-item client; tests assert query construction and synthetic responses without calling Security APIs. Preserve the test-owner CLI, file fixtures, process protocol versions, descriptors, Python adapter and legacy KeychainStore. Extract the existing strict typed anchor schema once, but require canonical bytes only in the protected backend so current unsorted/whitespace file fixtures remain valid. Canonical protected bytes are compact UTF-8 JSON in this exact field order: `anchor_version`, `host_id`, `host_generation`, `transition_id`, `transition_state`, `login_counter`; unsigned integers are unsigned base-10 without leading zeroes; stable transition ID is `null`; escape quote as `\"` and backslash as `\\`, and encode only U+0000–U+001F control characters as lowercase `\u00xx`, preserve other Unicode scalars as raw UTF-8 without normalization, do not escape slash, and add no whitespace/newline. Compare identifiers by UTF-8 bytes.

The owner receives a synchronous serialized injected anchor interface; concurrent/reentrant calls are rejected. Any failed or uncertain operation sets an irreversible terminal latch before return, sends no successful grant acknowledgment and makes no further backend call. The proposed default/test owner remains explicit and file-backed only under `--test-owner`; no live default constructor or automatic backend selection. Access group is entitlement configuration, not a lock. No file, legacy Keychain or best-effort fallback is allowed in a future production composition.

**Data Protection query/result contract implemented against fakes only:** constructed queries set the intended Data Protection Keychain flag, generic-password class, fixed service/account, configured access group, nonsynchronizable setting and after-first-unlock item class. The attributes-only all-results query validates an array containing exactly one permitted dictionary; the exact one-result query validates the returned item dictionary and canonical data. The adapter validates the actual `LAContext.interactionNotAllowed` property after provider return and before calling the injected client; if false it fails before client access. Tests use a fake client and explicit fake contexts to cover true/false/provider failure. R3.19 removes the concrete `SystemSecurityItemClient` and contains no `SecItem*` call. It therefore establishes no actual macOS Security result attributes, OSStatus behavior, access-group entitlement or signed-product no-UI behavior. A zero-result status remains unavailable/not-visible, not proof of physical absence; the two-query read is not atomic.

Reads never add/bootstrap/repair. Updates use only the exact fixed selector and expected transition, request no returned attributes/data, then perform the strict read sequence and require exact canonical byte readback. No add/delete, retry after uncertain write, repair, or fallback. Provisioning is absent from normal API and requires a separately reviewed explicit operation. SQLite and Keychain are not atomic; phase ordering and uncertain-result fencing remain. Readback is not rollback protection.
