**Owner and trust split:** the signed native supervisor owns anchor access, singleton lifetime, owner/child incarnation, exclusive operation grants, transition phase and logical channel-serving permission. One trusted packaged Python child owns SQLite and existing device/grant/session/ticket policy. The child is not an untrusted sandbox target; compromised authorized child code is inside this boundary. The first source slice excludes `PhoneRemoteService`, peers, receipts, leases, media, output queues and delivery; no service-output semantics are inferred from channel tests.

**Spawn and lifecycle:** verify the signed product/package, then launch only the fixed packaged interpreter, sealed dependencies and entrypoint with fixed args, isolated Python startup/import path, sanitized allowlisted environment, fixed working directory and no shell. No user-site, `PYTHONPATH`, `PYTHONHOME`, startup hooks, arbitrary module, unrelated inherited descriptors or secrets in argv/channel. Create a socket pair before spawn and pass only its child endpoint plus a duplicate singleton-lock FD; close every other FD. The socket endpoint is a per-spawn capability, never a listener; no reconnect or transfer. Do not authenticate arbitrary Python by UID, path, PID or interpreter signature. XPC remains deferred unless both processes have stable signing identities and exact mutual code requirements; Python interpreter identity alone does not bind the running module. Actual signed distribution/package identity and entitlements remain later work; no signing identity is chosen.

**Singleton:** before anchor read or spawn, acquire `flock(LOCK_EX|LOCK_NB)` on `~/Library/Application Support/com.mortimer.phone-authority/owner.lock`, after verifying user ownership and directory/file permissions. Never call `LOCK_UN`, unlink or recreate the inode. Child inherits the lock FD, retaining exclusion if the supervisor dies. Graceful shutdown stops grants, waits for the active grant to finish/abort, sends `owner.shutdown`, receives `child.shutdown_ack`, waits for child exit, then closes descriptors. On supervisor crash, successor waits until old child exits and releases its FD. Tests use a temporary precreated lock inode and test-only launch configuration, never this real user path. Same-user hostile processes can bypass advisory locking and are outside the trust boundary.

**Protocol:** `mortimer.phone-authority-channel.v1`; four-byte big-endian frame length + 1–65,536 strict UTF-8 JSON bytes. Reject duplicate keys, unknown fields, invalid UTF-8, non-object top-level, non-finite values, partial/zero/oversized frame. Exact common frame fields: `{protocol, version, kind, owner_incarnation, child_incarnation, sequence, correlation_id, payload}`. Version is exact JSON integer 1. Incarnation/correlation values are lowercase canonical UUID strings. Each direction begins at sequence 1, increments by exactly one, uses exact integers `1…2^64−1`, and closes before wrap. One request is in flight; response echoes its correlation ID. Native `owner.hello` is first frame (sequence 1, payload exactly `{max_frame_bytes:65536}`); child `child.ready` is sequence 1, same IDs/correlation and payload `{}`.

Child kinds are exactly `child.grant.acquire {operation}`, `child.anchor.read {grant_id}`, `child.anchor.advance {grant_id,step,state}`, `child.grant.release {grant_id}`, `child.grant.abort {grant_id}`, and `child.shutdown_ack {}`. Operation enum: `store.open`, `store.read`, `session.login`, `session.signout`, `authority.mutate`, `ticket.issue`, `ticket.consume`. `step`: `global_pending`, `global_stable`, `login_pending`, `login_stable`. Anchor state has exactly typed `anchor_version` (uint32 positive), `host_id` (nonempty string), `host_generation` (uint64), `transition_id` (null/nonempty string), `transition_state` (`stable`/`pending`) and `login_counter` (uint64). The only accepted initial anchor is version 1 with positive host generation, nonblank host ID, stable transition state and null transition ID; pending state is allowed only for same-grant write readback, never admission. Native success kinds: `owner.hello`, `owner.grant.acquired {grant_id,operation}`, `owner.anchor.state {grant_id,state}`, `owner.anchor.verified {grant_id,state}`, `owner.grant.released {grant_id}`, `owner.grant.aborted {grant_id,disposition}`, `owner.shutdown {reason:"requested"}`. Abort always returns disposition `unknown` if an acknowledgment is possible, then terminates the channel and marks authority unavailable pending fresh anchor/database reconciliation; absence of anchor advance does not prove SQLite was unchanged. Terminal `owner.error {code}` enum: `owner_busy`, `authority_unavailable`, `anchor_missing`, `anchor_locked`, `anchor_denied`, `anchor_corrupt`, `stale_incarnation`, `sequence_invalid`, `correlation_invalid`, `grant_invalid`, `phase_invalid`, `malformed_frame`, `unsupported_version`, `child_exited`. No raw OSStatus or exception details. All terminal errors close the channel. No SQL/path/account/schema-bootstrap/migration/reset/generic anchor overwrite message exists. `store.open` is only for a test-preprovisioned schema and allows stable read, never anchor advance.

**ProtectedAnchor mapping and legal phases:** because the existing Python `exclusive()` has no operation argument, the packaged child uses explicit `run_store_operation(operation, callable)` wrappers around each allowlisted store method and a separate `open_store(factory)` context for construction. These pass operation context directly, never infer it from the stack, and reject missing, nested, concurrent or mismatched contexts before store work. `exclusive` then acquires that wrapper-selected grant; normal exit sends release and waits for acknowledgment before the wrapper returns; exceptional exit sends abort and rethrows. Lost channel acknowledgment is `StoreUnavailable`/uncertain. Existing `read` maps to typed anchor read. Existing `write(state)` maps only to the one legal next typed transition, with native write/readback, followed by the store's own `read()` comparison. For `authority.mutate`: initial exact stable read → host generation +1 pending (same host/version/login counter; transition ID present) → allow exact pending readback in the same grant → stable state where only transition state changes to stable and transition ID clears → allow exact stable readback → normal release after final SQLite stable commit. For login: initial exact stable read → login counter +1 pending (host generation unchanged) → allow exact pending readback → stable state where only transition state and transition ID change → allow exact stable readback → release after session-row commit. Initial admission requires anchor version 1, positive host generation, nonblank host ID and stable/null transition. Pending reads are valid only for in-grant write readback, never admission. `store.open` is construction under a preprovisioned schema, then stable read and release; `store.read` is acquire, stable read, store read, release; `session.signout` is acquire, stable read, scoped SQLite signout, release; `ticket.issue` and `ticket.consume` each acquire, stable read, matching store operation, release. These wrappers return only after release acknowledgment and never advance the anchor. Native validates order, not SQLite contents; it trusts the authorized child’s phase acknowledgments. Exceptions never send normal release. Every abort has terminal disposition `unknown` because no anchor advance does not prove SQLite did not commit; the owner closes the channel and blocks authority pending fresh exact anchor/database reconciliation.

**Death and uncertainty semantics:** the supervisor stops issuing grants when it observes EOF, `waitpid` death or invalid frame—not at an unknowable instant of process death. The child separately stops starting operations when it observes EOF or a terminal protocol failure. A SQLite transaction already running may commit after owner death is observed but before child observes EOF. That completion is uncertain to the caller, must not be replayed, and requires exact anchor/database reconciliation before future admission. No service queue/output exists in this slice, so queued cancellation and already-emitted output behavior are deferred to the future `PhoneRemoteService` integration claim.
