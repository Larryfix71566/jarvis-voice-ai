# WS17 — Canonical held deployment tool

Bounded scope/CLI reservation `1f864e6`; application baseline `207bb8b`.
Only `scripts/deploy_main.sh` and directly related synthetic tests change.
The canonical file remains denied/human-only; no new mutable helper, API,
credential, model grant, launch label or configuration key is introduced.

`--install-held --approval-receipt FILE [--reuse-verification]` retains the
existing A/B/C verifier/snapshot/install flow but finishes as installed-held,
without starting services or opening the app. Target/CI/review records bind the
same non-documentation program tree; the caller must run the exact target's
canonical script. Records must come from the actual authorized review and CI
collection, not be asserted merely to make the deployer proceed. The unchanged
normal verification-reuse ceremony is not replaced by these records.

`--restore-local SNAPSHOT costs,vault` restores only explicitly named local
components after source, stable installed-bundle receipt, policy and launch-
envelope checks. Effective new-process environment/cwd and status-only loopback
health are checked. Failure quarantines services without reopening a prior
configuration. Admin is excluded pending separate passive/no-inference proof;
voice, extraction, scheduled probes and cleanup are not restoration targets.

`--rollback-held SNAPSHOT`, including the generated frozen `ROLLBACK.sh`,
first disables/unloads all fixed managed labels, verifies owned process exit and
quits only the known production app. It then restores verified prior code/app.
No services/app restart, settings/database rollback, source-policy weakening or
cleanup activation. Settings and databases are excluded from held code archives;
tracked private settings, unsafe archive paths/links, tampering, ambiguous state,
foreign leases and policy drift refuse. Lease recovery is deliberately manual:
never blindly reclaim a foreign/stale lease or kill a reused PID. If containment
or restoration cannot be proved, retain the shutdown and report failure.

The ordinary deployment entry refuses an active shutdown policy, per-service
guard or disabled override, avoiding accidental use of the legacy all-service
switch. Normal deployment behavior outside a hold and the existing authenticated
health helper remain intact. Prior legacy rollback scripts are not made safe by
this change; they must not be used for a held installation.

Validation: **86 focused tests PASS**, covering actual embedded code, synthetic
operator/filesystem failures, generated Bash rollback and existing deployment/
metadata contracts. Bash and embedded Python syntax pass. The JSON records exact
source/test/log hashes and preserves earlier non-passing test attempts. These
are deployment-tool tests, not a live deployment or a new application/native
acceptance campaign. The previously verified application bytes are unchanged;
final publication CI and exact-source external review remain separate gates.
Operational records and actual approval files stay local. No checkbox closes.

Approval schema (operator-created from verified evidence; placeholders cannot
pass): `version=1`, exact `target`, `review_receipt` path/hash and `ci_receipt`
path/hash. Review JSON needs exact `source`, program digest and completed
`no_blocking_findings` verdict. CI JSON needs exact `source`, matching digest and
all five named SUCCESS checks. Digests are computed from Git path/mode/blob
records, retaining executable/config/dependency/workflow/runtime-doc inputs and
excluding roadmap/plans/acceptance/log publications. Referenced private JSON must
be owned, regular, single-link and not group/world writable. This is a human-only
receipt-binding ceremony, not a replacement for independent review or source
approval. No passed approval record is generated by the implementation.
