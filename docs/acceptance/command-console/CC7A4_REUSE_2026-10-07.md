## Implemented behavior

- Native `WorkspaceStore` alone owns retained public source and freshness.
  Exact named/local subject keys preserve canonical result UUIDs, pins,
  comparison, inspector, reading state and Output history on refresh.
- The host queries an actual published native inventory, then the canonical
  UUID at that exact revision. The original model-observed voice list remains
  separate. Existing session/generation/revision and public-policy guards
  still apply; model-issued `weather_reuse` is refused.
- Fresh successful hits reopen through requested-arrival rules and avoid
  another fetch/display replay. Missing, expired or incomplete capability may
  use the existing guarded fetch. Unsafe identity/privacy, ambiguity,
  disconnect and timeout refuse without silently fetching.
- A fresh reference shows the original source-fetch clock and cached age.
  A genuinely newer complete-source refresh adds or updates one `Updated`
  reference to the same UUID per originating run, preserving its position.
  References contain bounded public title/time only; no source bodies enter
  transcript, persistence, sharing or inventory.
- Mixed cached/fetched halves retain the minimum original timestamp/expiry.
  If that aggregate clock has not advanced, the reference remains `Reopened`;
  newly available radar does not falsely renew weather freshness.
- Close/eviction removes the native cache with the result. Output records
  remain; a disabled reference cannot resurrect a closed result. References
  follow retained `ConversationStore` history across reconnects and clear
  with empty/cleared history, pruning or application lifetime.
