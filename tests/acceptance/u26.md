# U2.6 — Tendency Learning (execution card)

## Scope

Jarvis learns HOW the user likes things done over time, per instance:
inferred behavioral observations accumulate across sessions and promote
to active `user.style.*` facts only after recurring — while explicit user
statements always take effect immediately and can never be overwritten
by inference.

Plan basis: user directive 2026-08-08 ("I want Jarvis to learn the
tendencies and how the user likes things to be done over time … this
should be instance based"). Instance isolation comes free from the
plan §11 model: each instance owns its physical `jarvis.db`, so
observations, facts, and tendencies never cross instances.

## Design locks

- **Facts vs tendencies.** Facts (stated once) store immediately —
  U2.5 behavior, unchanged. Tendencies (inferred patterns) are only
  *observations* until the same key is seen in `PROMOTE_AFTER = 3`
  DISTINCT sessions.
- **Promotion never overwrites.** `promote_observations` can CREATE a
  `user.style.*` fact but never modify an existing one. Explicit
  statements ("I prefer short answers", "stop doing that") enter facts
  directly from the extraction prompt and always win.
- **Forget path.** `delete_fact(key)` removes the fact AND its
  accumulated observation evidence ("forget that").
- **Failure isolation** unchanged from U2.5: advisory context only,
  never raises, 30 s post-session cap.
- Extraction prompt extension is additive: a new `observations` array;
  older output without the key parses fine (tolerated, tested).

## Gates

- **G1 (unit)**: below-threshold no-promotion, promotion at threshold,
  distinct-session requirement, explicit-override protection,
  forget-path, end-to-end observation→promotion through
  `update_memory_from_session`, backward-compatible parsing.
- **G2 (locked expectations)**: `test_db.py` (+`observations` table,
  +`0004_observations`, +`idx_observations_key`). No test removed
  (invariant 2).
- **G3 (full gate)**: green, non-decreasing vs U2.5 baseline
  (223 passed / 3 skipped).
- **G4 (live, Mac)**: over several sessions, repeatedly steer Jarvis
  (e.g. ask for shorter replies); afterwards `sqlite3 data/jarvis.db
  "SELECT key, content FROM memories WHERE key LIKE 'user.style.%'"`
  shows the promoted tendency — and the next session's replies honor it.

## Evidence

- G1/G2: `33 passed` (test_memory 21 + test_db 5 + test_prompts 7).
- G3: `230 passed, 3 skipped in 88.66s` — up from the U2.5 baseline of
  223 passed / 3 skipped (invariant 2 holds). One design refinement
  during the gate: promotion may only CREATE a `user.style.*` fact,
  never overwrite one (explicit statements permanently outrank inferred
  evidence) — recorded here per the deviation convention.
- G4: deferred to Mac live verification.
