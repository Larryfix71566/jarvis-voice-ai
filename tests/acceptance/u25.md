# U2.5 — Persistent Memory (execution card)

## Scope

Jarvis remembers across sessions: keyed facts (user name, preferences,
projects) plus one running summary, injected into the Supervisor system
prompt at session start and refreshed from the session transcript after
the session ends.

Plan basis: upgrade plan §5 (context discipline) + user directive
2026-08-08 ("persistent memory … remember the user's name and all things
previously discussed … memory file summarized to provide context").
Recorded here as phase U2.5; the plan document gains the U2.5 entry in
its next revision (docs-only change, no invariant impact).

## Design locks

- Memory is **advisory context only** — it can never trigger tool calls or
  actions; it is text in the system prompt.
- Storage: SQLite `memories` table (migration `0003_memory`), single
  running-summary row, facts upserted by dotted key
  (`user.name`, `user.preference.*`, `project.*`).
- Extraction: one LLM call per ended session, strict-JSON contract
  (`{"facts": [...], "summary": "..."}`), unparseable output leaves
  memory untouched.
- Failure isolation: every public function in `jarvis/memory.py` degrades
  to a safe empty result; the post-session update is hard-capped at 30 s
  and can never delay shutdown (mirrors TranscriptLogger's
  "logging must never break audio" rule).
- Prompt: `SUPERVISOR_PROMPT` gains `{memory_context}`; rule 3's
  "stored memories" phrase now refers to notes (librarian), while
  long-term memories are explicitly "already known — never delegate to
  recall them".

## Gates

- **G1 (unit)**: `tests/unit/test_memory.py` — upsert-by-key,
  single-summary invariant, render ordering/caps, never-raise on broken
  DB, strict-JSON parsing (incl. fence stripping and malformed-fact
  drops), end-to-end session update with a fake client, skip-without-
  user-turns, unparseable-output safety, previous-summary carry-forward,
  JARVIS_DB_PATH override.
- **G2 (locked expectations)**: `test_db.py` (+`memories` table,
  +`0003_memory`, +`idx_memories_fact_key`), `test_prompts.py`
  (memory placeholder formatted, memory section present). No test
  removed; counts strictly increase (invariant 2).
- **G3 (full gate)**: `python3 -m pytest -q` green, count non-decreasing
  vs U1.5 baseline (208 passed / 3 skipped).
- **G4 (live, Mac)**: two-session check — tell Jarvis your name in
  session 1, disconnect; reconnect and confirm Jarvis greets/addresses
  you by name without being told again.

## Evidence

- G1/G2: `26 passed` (test_memory 14 + test_db 5 + test_prompts 7).
- G3: `223 passed, 3 skipped in 72.13s` — up from the U1.5 baseline of
  208 passed / 3 skipped (invariant 2 holds: no test removed, count
  strictly increased). One wiring-level fix during the gate:
  `jarvis/agents/supervisor.py` (Phase-2 direct-mode orchestrator) also
  formats `SUPERVISOR_PROMPT` and needed the same `{memory_context}`
  argument — recorded here per the deviation convention.
- G4: deferred to Mac live verification (like U1-G3, U1.5-G3).
